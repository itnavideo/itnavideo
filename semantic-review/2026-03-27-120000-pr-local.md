# Registry-driven Itnavideo homepage with scoped admin context

The redesign replaces generic homepage claims with a ten-workflow registry consumed by the workflow gallery, navigation, footer, metadata, and structured data. It also limits admin session state to the `/admin` segment while retaining the login gate and sidebar consumers. The main shipping gaps are in media failure behavior, preview framing, and homepage title composition; the rendered pricing and FAQ paths use the canonical plan and language data. Shell execution failed before producing output, so this pass could not verify the `git diff main` boundary or execute `npx tsc --noEmit`; findings are restricted to the requested source surfaces but should be reconciled with the actual diff.

Watch for: **confirmed** video errors bypass an available poster; **confirmed** vertical posters and videos use inconsistent fitting in a non-9:16 frame; **confirmed** the homepage title includes the brand before inheriting a root brand template; **confirmed** stale, noncanonical pricing remains in an unmounted legacy component; **confirmed** requested-surface files retain unused imports; **likely** Navbar’s hardcoded featured lookup can fail when the canonical registry changes.

**Verdict**: NEEDS_CHANGES

## High-level view

The workflow gallery uses one DOM tree and one `IntersectionObserver`, and it mounts at most one `<video>` at a time. The intended performance boundary is sound, but the failure branch suppresses the poster precisely when video playback fails, and inactive/active states switch between cropped and contained media.

The registry has ten entries with the expected six/three/one split, and every dashboard/public route inspected resolves to an existing route or canonical alias. Navbar and Footer derive labels and links from it, although Navbar’s separately hardcoded featured IDs and icon map remain a synchronization point. Hero claims about accepted media, cloud rendering, free signup, output families, and English/Roman-Hinglish support align with the inspected workflows and project policy.

The visible homepage pricing is `SubscriptionPricingCards`, backed by `lib/billing/plans.ts`; FAQ copy and FAQ JSON-LD match the ten workflows, free-credit wording, workflow-dependent costs, and current language policy. `PricingSectionClient.tsx` is not imported, but it still contains old prices and retired workflow names.

`AdminProvider` wraps the admin layout including `/admin/login`; all `useAdmin` consumers remain below it, AppChrome suppresses public chrome on admin routes, and the root Toaster remains available. The relocation preserves login, redirect, sidebar, and logout behavior while avoiding an admin session request on public pages.

## Video failure bypasses the available poster

The fallback at `components/landing/WhatCanYouCreate.tsx:286-298` is entered when `videoFailed` is true, but its poster condition also requires `!videoFailed`. This **confirmed** contradiction renders `MediaPlaceholder` even when `posterSrc` is healthy. Remove `&& !videoFailed` from the poster condition and retain `posterFailed` as the poster-specific guard.

The short-form box at `components/landing/WhatCanYouCreate.tsx:261-263` is 9:12 on mobile and 9:11 at `sm`, while these registry outputs are 9:16. Inactive posters use `object-cover` at lines 286-295 and active video uses `object-contain` at lines 272-282, a **confirmed** framing change from cropped to letterboxed when playback starts. The smallest fix is one fit mode for both; switching the box to 9:16 is only necessary if the card must show exact export framing.

`preload="auto"` at line 278 applies only to the active video, so the component does not create concurrent video downloads for all cards.

## Homepage title inherits a second brand suffix

`app/page.tsx:22` sets `Free AI Video Generator & Maker | Itnavideo`, while `app/layout.tsx:50-53` defines `%s | Itnavideo` for child titles. This is **confirmed** to supply both a branded child title and branded parent template, allowing `Free AI Video Generator & Maker | Itnavideo | Itnavideo`. Remove the page suffix or declare `{ absolute: 'Free AI Video Generator & Maker | Itnavideo' }`; Open Graph and Twitter titles should keep their explicit suffix because they are separate fields.

## Navbar keeps a second workflow identity list

Navbar resolves five hardcoded IDs through `find(...)!` at `components/layout/Navbar.tsx:46-66` and indexes a separate icon map at lines 38-49. This is a **likely** runtime failure after a canonical ID rename/removal because module evaluation dereferences `workflow.name` on `undefined`; a new workflow without an icon can also render an undefined component. Derive featured rows from a registry flag, or filter failed lookups before mapping. Current routes are intact because all present IDs match.

## Legacy pricing remains contradictory even though it is not rendered

`app/page.tsx:15,147` mounts `components/landing/PricingSection.tsx`, which sources the visible cards from `lib/billing/plans.ts`. `components/landing/PricingSectionClient.tsx` has no importer, but lines 75-224 define obsolete $0/$2/$9/$24/$49 plans and retired/noncanonical names including Long Video Pro, Auto Draw Explainer, Dynamic Creator Reel, and Custom AI Director. This is **confirmed** dead, contradictory data. If the file is in the redesign diff, remove it from the diff/delete it; if retained for reuse, replace its arrays with `pricingPlans` and `HOMEPAGE_WORKFLOWS`.

## Admin scope is intact, but requested files retain unused symbols

Provider coverage is preserved at `app/admin/layout.tsx:21-25`: login consumes `useAdmin` at `app/admin/login/page.tsx:5,14`, the gate at `app/admin/layout.tsx:29`, and the sidebar at `components/admin/AdminSidebar.tsx:5,23`. AppChrome’s `/admin` focused-route branch keeps public Navbar/Footer out of the shell, while the root Toaster still covers login feedback.

There are **confirmed** unused imports in the requested surfaces: `React` in `app/page.tsx:1`; `Search`, `ExternalLink`, `ShieldCheck`, `Zap`, `Bell`, `Sparkles`, and `HelpCircle` in `app/admin/layout.tsx:9-18`; and `Video`, `Zap`, `ShieldCheck`, `HelpCircle`, and `Link` plus three unused price parameters in `components/landing/PricingSectionClient.tsx:7-30,225`. `tsconfig.json` does not enable `noUnusedLocals`/`noUnusedParameters`, so these are not established `tsc` failures, but the configured Next TypeScript ESLint preset can reject them. Remove only the unused imports/parameters.
